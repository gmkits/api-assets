# `.hday` v2 与日历运行时 4 GiB 历史验收

> 这是 Monorepo 迁移前的同机基线。`data/date-assets`、多 JDK 和 `/api/v1`
> 记录的是当时的测量现场；新实现统一使用 `apis/calendar`、JDK 21 和
> `/v1/calendar`，这些旧命令不再是当前构建入口。

环境：

- Apple M2，8 个逻辑 CPU，16 GiB 主机内存
- BellSoft Liberica JDK 8.0.492 / 25.0.3 LTS
- Homebrew OpenJDK 17.0.19 / 21.0.12
- JMH 1.37、G1、`-Xms4g -Xmx4g`
- 1 × 1 s 预热、3 × 1 s 测量、1 fork；冷路径复测使用 2 次预热和 5 次测量
- 外部统一资产：`data/date-assets`

## JMH

| Benchmark | JDK 8 | JDK 17 | JDK 21 | JDK 25 | 单位 |
| --- | ---: | ---: | ---: | ---: | --- |
| `singleDay` | 197,750,302 | 338,000,545 | 352,376,326 | 349,726,288 | ops/s |
| `isHoliday` | 215,403,817 | 370,165,688 | 395,394,748 | 387,356,101 | ops/s |
| `month` | 59,840,015 | 110,566,217 | 102,600,579 | 116,932,844 | ops/s |
| `countWorkdaysForYear` | 126,126,880 | 178,805,161 | 193,810,799 | 183,424,372 | ops/s |
| `concurrentMixedQueries` | 119,542,037 | 197,745,895 | 215,995,398 | 197,914,268 | ops/s |
| `lunarConversion` | 20,632,833 | 23,266,628 | 23,554,730 | 22,256,241 | ops/s |
| `coldBundleParse` | 58.20 | 42.34 | 43.90 | 46.11 | µs/op |
| `firstServiceQuery` | 238.83 | 212.73 | 241.96 | 210.99 | µs/op |

JDK 8/25 的上一轮同机热查询基线中，`singleDay` 分别为 32,503,949 /
46,912,942 ops/s，`isHoliday` 分别为 32,070,109 / 46,529,791 ops/s。
v2 没有热查询回退。收益主要来自按 manifest 年份范围建立的紧凑缓存索引；
合法默认地区的缓存命中不再分配字符串键，也不再重复执行正则和 manifest 查询。
JDK 25 的 GC profiler 显示这两个热查询的分配量约为 `10^-5 B/op`，可视为测量噪声。

用同一段预热/测量程序在 JDK 8 比较 2026 年 bundle 冷解析，v1 中位数为
54.577 µs/op，v2 为 50.210 µs/op，v2 快约 8.0%。这组数用于版本差值；
表内的 JMH 数值用于观察四个 JVM 的最终状态。

## 保留内存与文件体积

使用 JOL 遍历加载 2000–2026 全部 27 年后的 `HolidayService` 对象图：

的目标。

## HTTP API

Spring Boot 2.7.18、内嵌 Tomcat、100,000 请求、并发 100，同机回环：

| JVM | v1 基线 QPS | v2 QPS | 失败 | 平均延迟 | P95 | P99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Liberica JDK 8 | 21,894.95 | 28,755.11 | 0 | 3.478 ms | 5 ms | 8 ms |
| Liberica JDK 25 | 21,505.47 | 27,257.40 | 0 | 3.669 ms | 5 ms | 7 ms |

接口为
`GET /api/v1/day?date=2025-10-06&regionCode=CN`，响应 642 bytes。
这是无 TLS、无网关、无访问日志的本机回环结果，不是生产容量承诺。

## 1.0.0-rc1 发布候选复测（2026-08-01）

发布候选改为单一 `calendar.cdat`，并将可选 HTTP 服务升级到 Spring Boot 3.5.16 / Java 17+。
JDK 25、4 GiB、2 × 1 s 预热、3 × 1 s 测量的关键 JMH 结果：

| Benchmark | 结果 | 相对上表 JDK 25 |
| --- | ---: | ---: |
| `singleDay` | 351,994,926 ops/s | +0.65% |
| `isHoliday` | 383,381,557 ops/s | -1.03% |
| `countWorkdaysForYear` | 187,138,808 ops/s | +2.03% |
| `lunarConversion` | 23,017,689 ops/s | +3.42% |
| `coldBundleParse` | 43.566 µs/op | 快 5.52% |

热单日与状态查询的分配量仍约为 `10^-5 B/op`。同机 HTTP 在先用 20,000 请求预热后，
两轮 100,000 请求、并发 100 的结果为 30,201.95 / 29,952.29 QPS，均为零失败；
较上表 Spring Boot 2.7 的 JDK 25 结果没有回退。未充分预热的首轮约 22.6K QPS，
因此这些数字仍只用于本机版本比较。

## 命令

```bash
java -Xms4g -Xmx4g \
  -Dcn.holiday.assets.path=/absolute/path/data/date-assets \
  -jar java/holiday-benchmarks/target/benchmarks.jar \
  -wi 1 -i 3 -w 1s -r 1s -f 1

java -Xms4g -Xmx4g -XX:+UseG1GC \
  -jar java/holiday-api/target/holiday-api-1.0.0-rc1.jar

ab -k -n 100000 -c 100 \
  'http://127.0.0.1:8080/api/v1/day?date=2025-10-06&regionCode=CN'
```
