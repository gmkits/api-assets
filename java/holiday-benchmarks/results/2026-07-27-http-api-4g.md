# 4 GiB HTTP API 本机压测

环境：

- Apple M2，8 个逻辑 CPU，16 GiB 主机内存
- BellSoft Liberica JDK 8.0.492 / JDK 25.0.3 LTS
- Spring Boot 2.7.18、内嵌 Tomcat
- `-Xms4g -Xmx4g -XX:+UseG1GC`
- ApacheBench：100,000 请求，并发 100
- 接口：`GET /api/v1/day?date=2025-10-06&regionCode=CN`
- JSON 响应：580 bytes

| JVM | QPS | 失败 | 平均延迟 | P95 | P99 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Liberica JDK 8 | 21,894.95 | 0 | 4.567 ms | 10 ms | 21 ms |
| Liberica JDK 25 | 21,505.47 | 0 | 4.650 ms | 9 ms | 17 ms |

这是同机回环、无 TLS、无网关、无访问日志、无响应缓存的短时结果，不是生产容量承诺。
两个 JVM 的差异低于这种短测的正常噪声，说明当前 HTTP 吞吐的主要成本是
Spring MVC/Tomcat 和 JSON 序列化，而不是节假日算法。

ApacheBench 本次没有复用 keep-alive，因此结果还包含每个请求的本机 TCP 连接成本。
生产环境应使用 wrk/k6 在独立压测机上带真实 TLS、网关和日志配置再次测量。

命令：

```bash
java -Xms4g -Xmx4g -XX:+UseG1GC \
  -jar java/holiday-api-j8/target/holiday-api-j8-1.0.0-SNAPSHOT.jar

ab -k -n 100000 -c 100 \
  'http://127.0.0.1:8080/api/v1/day?date=2025-10-06&regionCode=CN'
```
